structures
    Структуры - группируют поля под одним именем.
    в Go есть инкапсуляция и методы, но отсутствует наследование и классический полиморфизм. Вместо базовых классов и подтипов Go предпочитает композицию и Dependency Injection.
    Dependency Injection - паттерн проектирования, при котором объект получает свои зависмости извне, а не создает их самостоятельно.
    Метод - это функция, которая связана с определенным типом через ресивер.
    Композиция - вместо наследования.
    Теги - это строки в кавычках после типа поля.

interfaces
    interface - определяет поведение
    в го - неявное наследование -  если тип удоволетворяет требуемуему поведению, он считается подходящим.
    Полиморфизм - одна переменная может хранить переменные разных типов, если они удовлетворяют интерфейсу.
    Пустой интерфейс не содержит методов, поэтому любой тип удовлетворяет ему. Аналог Object в Java или Any в Cotlin. В версии 1.18 ввели идентификатор Any - это алиас для пустого интерфейса.
    Interface Segregation Principle - принцип разделения интерфейса - классы программмы не должны зависеть от тех методов, которые они не используют (Лучше много маленьких интерфейсов, чем один огромный).
    Интерфейс равен nil тогда и только тогда, когда в нем нет ни типа ни значения. Если внутри лежит указатель конкретного типа, это уже не nil-интерфейс!

goroutines
    Горутина - легкий поток, управляемый планировщиком Go, а не операционной системой. Они запускаются через ключевое слово go и их может быть десятки тысяч одновременно. Каждая горутина занимает всего 2КБ памяти на старте - в десятки раз меньше, чем поток.

    Множество горутин назначается на меньшее количество потоков, а Go сам управляет переключением между ними.
    
    Для того чтобы обмениваться сообщениясм между горутинами го предлагает каналы. Не общайтесь через разделяемую память - разделяйте через общение.

    main - это тоже горутина и если она завершится, остальые горутины будут принудительно остановлены, поэтому нужно явно ожидать их завершения.

    sync.WaitGroup - надежный способ ждать завершения нескольких горутин. Это счетчик который увеличивается на количество горутиг с помощью метода Add(), затем каждая горутиа должна вызвать done при завершении, тогда счетчик уменьшается, а wait блокирует основную горутину до тех пор, пока счетчик не станет нулем.

    Буферизованный канал - отправка блокируется, когда буфер заполнен, а получение - когда буфер пуст.
    Удобно в ситуации, когда сообщения приходят пачками и нам не обязательно обрабатывать их мнгновенно.

    Закрытие канала сообщает получателям, что больше сообщений не будет. При закрытом канале отправка вызывает панику. Получение из закрытого канала дает zero value и false во втором возвращаемом параметре.
    Закрывает канал только отправитель.
    Если отправителей несколько - используйте WaitGroup, чтобы убедиться, что все завершили отправку перед закрытием.

    Можно использовать канал пустых структур как сигнальный канал.

    select - когда надо ждать несколько источников данных одновременно.

    sync.Mutex - защитить общий ресурс от одновременного доступа.

    Worker Pool - это набор заранее запущенных рабочих процессов иди потоков, которые берут задачи из общей очереди и выполняют их параллельно.

    Context - помогает предоставить сигнал об отмене и установить дедлайн. 
    - Withcancel - создает дочерний контекст с новым каналом данных. Вызывается при вызове cancel или когда родительский контекст завершен.
    - WithDeadline - устанавливает дэдлайн
    - WithTimeout - устанавливает таймаут
    done возвращает канал, который закрывается при отмене или истечении времени.

http-server
    handle function - функция, которая связывает URL-путь с обработчиком запросов.

    Мультиплексор (Mux) - компонент, который направляет HTTP-запросы в нужный обработчик по URL.

    Handler - функция, которая обрабатывает HTTP-запрос и формирует HTTP-ответ.

    WriteHeader должен вызываться до записи тела - иначе всегда будет 200

    Middleware - это функция, которая принимает http.Handler и возвращает http.Handler.

    CORS - механизм, который разрешает или запрещает запросы между разными доменами.
